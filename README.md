# МАГНИТ РЦ — версия 2.17

## Вкладка «Макрос палет»: строго два Excel по предоставленным образцам

Основание: файлы, переданные пользователем 22.11.2026:

1. `MAGNIT_MACRO_PALLETS_2026-11-22.xlsx` — **первая таблица**.
2. `Запрос на Спуск паллет 22.11.2026.xlsx` — **вторая таблица**.
3. `Запрос на Спуск паллет 01.11.2026 (1).xlsx` — **пример заполненного запроса**, а не файл для импорта.

### Входные данные и выборка

- На вкладку загружается **одна или несколько** реальных сводных выгрузок по палетам `.xlsx`, содержащих `номер`, `код`, `назв`, `МО`, `МП` и `Дата формирования` / `Дней на хранении`.
- В выборку попадает **ФРЕШ/ФРОВ: свежие фрукты, овощи, зелень, листовые салаты и свежие грибы**, включая петрушку, кинзу, укроп, рукколу, салатные миксы, шпинат и др. Название сверяется с перечнями признаков ФРОВ; готовые блюда, консервация, сухие специи и другие переработанные продукты исключаются. Поскольку в исходном отчёте по палетам нет отдельного достоверного столбца категории ФРОВ, неоднозначные наименования не включаются автоматически, чтобы не подменять факты догадками.
- Недавние палеты — до 3 дней включительно, давние — старше 3 дней. Порог и дата проверки изменяемые. Возраст от даты формирования не всегда равен дате физического поступления.
- По умолчанию 1,5% по каждой возрастной группе, проценты редактируемые.
- **«Количество палет к спуску»**: пустое поле — расчёт по процентам; введённое целое число — приоритетное общее количество, распределяемое между двумя возрастными группами. Количество не может превысить реально доступные палеты; дефицит выводится предупреждением.
- **«Приоритетно по коду, палет»**: редактируемое число. Применяется только при заполненном коде, в пределах общего количества и фактического наличия. При недостатке появляется предупреждение; недостающие палеты не придумываются.
- Вариант смены для второго Excel выбирается пользователем: **«День»** или **«Ночь»**. По умолчанию — «День»; все выбранные палеты помещаются только на указанный лист. Неуказанная смена не заполняется автоматически.
- По желанию применяется фильтр поставщика, если его значение подтверждается полями исходной выгрузки; при отсутствии такого подтверждения выдаётся ошибка, не создаются ложные строки.
- Случайность — фиксируемый seed PRNG; повторное формирование создаёт новое зерно. Готовые палеты сортируются по `МП`.

### Две кнопки и точная структура книг

**Кнопка №1 — «Скачать таблицу №1 · Проверка палет»:**

- Лист `Проверка палет` с колонками `номер`, `код`, `назв`, `МО`, `МП`, пустая F, `Результат проверки` (G). Исходный короткий шаблон.
- Лист `Протокол отбора` с двумя колонками `Параметр`, `Значение` и теми же 17 параметрами, что в первом исходном файле. Числа обновляются под выборку.

**Кнопка №2 — «Скачать таблицу №2 · Запрос на спуск»:**

- `День` — 19 колонок, в порядке из `Запрос на Спуск паллет 22.11.2026.xlsx`.
- `Ночь` — точно такие же 19 колонок.
- `Лист1` — **полный накопительный список реальных буферных пар** `номер`, `МП` из текущих загруженных исходных Excel, включая другие категории товара (это именно буферный справочник, а не список спуска).
- `Унифицированный коментарий` — четыре справочные формулировки, в тех же строках A2:A5, что в шаблоне. Это подсказка, а не результат проверки.

В **обоих** файлах поле `Результат проверки` остаётся пустым. В запросе также остаются пустыми `Процент бракапо итогам разбраковки` и `Комментарий (ОКК)` (колонки Q, R, S). Только менеджер после осмотра вписывает их вручную. Никаких других листов, автоматических значений комментариев или придуманных товарных позиций не добавляется.

### Дополнение 2.17 — ФРЕШ/ФРОВ

- Расширено распознавание **всей свежей зелени и салатных культур**: петрушка, кинза, укроп, базилик, мята, мелисса, тархун, розмарин, тимьян, чабрец, щавель, шпинат, микрозелень, мангольд, руккола, кресс-салат, салатные миксы, шампиньоны и другие наименования из списка признаков.
- Позиции «САЛАТНЫЙ МИКС Руккола / Мангольд / Мизуна» и «САЛАТНЫЙ МИКС руккола/мангольд/шпинат» больше не пропускаются. Переработанные товары со словами «зелень», «укроп», «салат» по-прежнему не спускаются.
- **Без изменений:** проценты 1,5% + 1,5%, ручное количество, приоритетный код и количество, выбор смены, два исходных Excel-шаблона и пустые результаты осмотра. «Лист1» содержит все фактические буферные палеты.

### Проверка версии 2.17

На реальном источнике `pallet_summary (1)(1).xlsx`, при дате 22.11.2026, ручном общем количестве **18** и приоритетном коде **3412070012** в количестве **4**, получено 8 недавних и 10 давних палет, из них 4 с заданным кодом. Сформировано два отдельных XLSX.

Проверены имена и количество листов (2 и 4), исходные имена 19 колонок, перенос палет между листами `День` и `Ночь`, полный `Лист1` из 12 138 подтверждённых буферных записей и отсутствие значений в Q/R/S. Оба файла прошли проверку ZIP-целостности и доступны для скачивания в тестовом браузере.

### Установка на GitHub Pages

Распакуйте ZIP, замените `index.html`, всю папку `assets/` и `README.md` в репозитории. Перезагрузите сайт с Ctrl+F5 и убедитесь, что версия **2.17**. Сайт остаётся браузерной реализацией алгоритма отбора — не является VBA-макросом.

**Конфиденциальность:** не размещайте коммерческие таблицы в публичном репозитории. В комплекте сайта уже есть ранее встроенные справочники НТЗ и Эталона, которые могут быть доступны посетителям GitHub Pages. Для конфиденциальных справочников требуется защищённое размещение.


## АКТ комиссионной приёмки — версия 2.16

Новая вкладка в главном меню «АКТ комиссионной приёмки» (а также карточка на главной).

1. Заполните должность и ФИО составителя, номер заявки и заказа, наименование и код товара, характер брака/нестандарта, проценты и прочие замечания.
2. Укажите ФИО для расшифровки подписей МОКК, СМОКК и НОКК. Места подписи намеренно оставлены пустыми — подписание после осмотра.
3. Укажите две даты: составления акта и проведения комиссионной приёмки.
4. Справа отображается печатный предпросмотр формата A4 с локальным логотипом МАГНИТ и адресом РЦ. Если текст превышает одну страницу, появится предупреждение — для печати его нужно сократить.
5. Кнопка **«Скачать акт Word (.docx)»** создаёт документ на вашем устройстве. Содержимое сохраняется без использования сторонних веб-сервисов и без загрузки на сервер. Файл открывается в Microsoft Word, LibreOffice и аналогах.
6. Кнопка **«Печать / сохранить PDF»** использует диалог печати браузера: выберите A4 и печать на принтер или «Сохранить как PDF».
7. Кнопка «Очистить поля» удаляет все введённые данные, но восстанавливает адрес РЦ.

Адрес по умолчанию: **385225, Республика Адыгея, Теучежский район, хутор Кочкин, ул. Логистическая, д. 1**. Он редактируется непосредственно в форме. Обратите внимание: Республика Адыгея — отдельный субъект РФ, а не Краснодарский край.

Поля умышленно **не заполняются выдуманными значениями**, включая даты и фамилии комиссии. Информация о составе документа — из требований пользователя; это не утверждённый юридический бланк без внутреннего согласования. Логотип оформлен как локальный графический элемент, сайт не зависит от внешней загрузки изображений.

Новые файлы: `assets/act.css`, `assets/act.js`, `assets/magnit-logo.png`, `assets/magnit-logo.svg`. Сохраняйте папку `assets` целиком при обновлении GitHub Pages.
