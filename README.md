# МАГНИТ РЦ — версия 2.9

Статический сайт для GitHub Pages. Версия 2.9 добавляет новый раздел **«Претензии магазинов МАГНИТ»**, сохраняя модули товарного запаса, критики ТЗ, Эталона, возвратов ГТ и конструктора претензий Гранд-Трейд версии 2.8.

## Претензии магазинов МАГНИТ

1. В меню открыть **«Претензии магазинов»**.
2. Загрузить Excel `.xlsx` из модуля претензий магазинов (`claims_export_...xlsx`). Можно загрузить **один файл**, который содержит обращения за оба дня, либо **несколько файлов по очереди**. Данные предыдущих файлов не пропадают, пока не нажата кнопка «Очистить загруженные файлы».
3. Указать дату окончания периода. Сайт автоматически берёт **этот день и предыдущий календарный день** по полю `Дата обращения`. При открытии раздела конечная дата заполняется по локальной дате браузера, но её можно изменить для исторических отчётов.
4. Выбрать **порог массовости** (по умолчанию 2 обращения; можно выбрать 1, 3, 5, 10).
5. Нажать **«Сформировать массовость»**. На экране появятся показатели, «Массовость по товарам», «Критика по характеристике товара». Кнопка «Обращения» раскрывает исходные данные конкретной группы. Поиск выполняется по товарам, характеристикам, производителям, магазинам.
6. При необходимости скачать Excel: **«Массовость», «Критика», «Все товары», «Обращения», «Контроль»**. Если браузер не начал скачивание, рядом появляется резервная ссылка.

### Поддерживаемый формат выгрузки

Формат проверен по исходному файлу `claims_export_2026-11-22T04_50_24.184790727Z.xlsx` с листом `Sheet0` и 56 столбцами. Обязательные названия:

- `Код товара`
- `Наименование товара`
- `Дата обращения`
- `Характеристика товара/прихода`
- `Производитель`

Дополнительные используемые названия: `guid`, `id`, `Код ТО`, `Наименование ТО`, `Филиал`, `Кол-во брак`, `Комментарий ТО`, `Причина списания`, `Статус`.

**Правила обработки:**
- В отчёты попадают только фактические обращения за выбранные два дня. Коды и названия товаров не создаются из Эталона или НТЗ.
- Записи без реального кода товара, наименования или корректной даты обращения пропускаются. Неизвестные производители и характеристики остаются пустыми, а не заменяются придуманными.
- При повторной загрузке одна претензия с тем же `guid` считается один раз. Если `guid` отсутствует, используется `id`, а затем фактические поля строки.
- Массовость по товару считается по коду товара. Критика — по коду товара и характеристике; варианты « Гниль» и «Гниль» объединяются при группировке, но исходное значение сохраняется в листе «Обращения» после удаления лишних пробелов.
- Количество магазинов — количество уникальных кодов `Код ТО` (если код отсутствует, используется название магазина).
- Производители берутся из файла как есть, без автоматического объединения похожих написаний и без поиска во внешних справочниках.
- Если за один из дней нет обращений, сайт сообщает об этом; дата никогда не подменяется.
- В отчёте «Контроль» сохраняются количество повторов, даты, выбранный порог и показатели периода.

### Установка

Содержимое архива загрузить в **корень репозитория**, включая `index.html`, `assets/` и `README.md`. В GitHub Pages выбрать публикацию из нужной ветки. Обновить страницу в браузере `Ctrl+F5`, убедиться, что указан номер версии **2.9**. Никакие серверные API или ключи не требуются; Excel обрабатывается локально в современном Chrome / Edge.

### Безопасность

**Не публикуйте конфиденциальные выгрузки претензий в GitHub.** Загруженные пользователем Excel-файлы обрабатываются в браузере и не отправляются на сервер. Однако исходная сборка содержит встроенные справочники НТЗ / Эталон из предыдущих версий сайта: если разместить эту сборку в **публичном** GitHub Pages, встроенные справочники станут общедоступны. Для конфиденциальных нормативов нужен защищённый способ размещения.

### Технические файлы

- `assets/store-claims-core.js` — проверяемая бизнес-логика разбора, дедупликации и массовости.
- `assets/store-claims.js` — загрузка файлов, таблицы сайта, выгрузка Excel.
- `assets/store-claims.css` — минималистичный адаптивный дизайн.
- `assets/xlsx-lite.js` — автономное чтение XLSX.
- `assets/export.js` — формирование XLSX локально в браузере.

### Проверка на эталонной выгрузке претензий

Все 57 обращений относятся к 21.11.2026, за 22.11.2026 в файле записей нет. Повторная загрузка того же файла правильно исключает 57 дублей, сохраняя 57 уникальных обращений. Скачанный XLSX проверен на наличие 5 листов. Дизайн проверен на широком экране и на ширине 390 пикселей.
