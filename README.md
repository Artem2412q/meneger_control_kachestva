# МАГНИТ РЦ — версия 2.6 (только подтверждённые ТП)

Сайт для GitHub Pages, автоматизирующий Excel-отчёты распределительного центра.

## Каждый день — только два Excel на один отчёт

В разделе **«Товарный запас»** загрузите:

1. `rep_turnover_saldo_for_logist_excel.xlsx` — «Сальдово-оборотная ведомость для логистов»;
2. `rpt_levelservice_api.level_service_hd_gk_eday_hm.xlsx` — «Уровень сервиса по товарным позициям для ГК».

Затем нажмите «Проверить и объединить файлы», выберите дату и «Скачать готовый отчёт Excel». Можно брать вчерашнюю дату.

В разделе **«Критика»** загрузите **другую пару** файлов с этими же названиями, но с данными **за сегодняшний день**. Нажмите «Проверить критику за сегодня», затем «Скачать критику Excel». Сайт проверяет сегодняшнюю дату в уровне сервиса. Дату сальдо автоматически проверить нельзя, потому что в исходной сальдовой ведомости нет отдельного столбца даты выгрузки. Выбранные файлы обрабатываются локально в браузере.

**Отдельно загружать НТЗ не нужно.** Ранее появлявшееся сообщение «Для выгрузки Критики необходимо подключить НТЗ» — ошибка старой версии.

## Встроенные справочники

- `assets/norms.js` содержит **основной НТЗ за 24.10.2026 (1 148 товарных кодов)** из предоставленного образца, нормативы НК/КК, три полных архивных среза **15.05.2026, 16.05.2026, 09.10.2026** (каждый по 1 148 товарных кодов), 627 уникальных кодов цветов, а также список товарных позиций образца. Этот файл автоматически загружается при открытии сайта независимо от локального хранилища.
- `assets/etalon.js` содержит Эталон — **4 287 уникальных кодов ТП** из предоставленного `Эталон.txt`.
- Основной НТЗ и исторический архив сохраняются в итоговой книге как листы `НТЗ` и `Архив НТЗ`. НК/КК в отчёте связаны формулами с НТЗ.
- Если код ТП отсутствует в основном НТЗ или в выбранном срезе, норматив **не придумывается и не подменяется нулём**. Отмечается `НЕТ В НТЗ`, подробности — в листе `Контроль`.
- Архив НТЗ не подменяет основной срез автоматически — период выбирается сознательно.
- Обновление НТЗ в будущем требует отдельно обновить встроенный `assets/norms.js` и опубликовать новую версию; две ежедневные выгрузки не содержат достоверных нормативов и сами их не обновляют.

## Состав Excel

При формировании применяются заливка первой колонки «Код товара» голубым цветом, синие заголовки, зелёные нормативы НК/КК и комментарии, проценты УС с двумя знаками, остальные числовые показатели с двумя знаками, красное выделение критических отклонений. Сохраняются формулы без преждевременного округления. Дополнительные листы: `Эталон ТП` (только найденные в двух ежедневных источниках), `код цветы`, `Цветы` (для товарного запаса), `УС` (для товарного запаса), `Контроль`. Отсутствующие исходные данные остаются пустыми, а не автоматически нулевыми.

Выбор товарных кодов: «Эталон — только подтверждённые ТП», «Овощи и фрукты», «Все позиции выгрузок» и «Только коды цветов». Для критики точные бизнес-правила определения состава «критических» ТП могут уточняться в последующих примерах.

## Установка на GitHub Pages

1. Распакуйте архив и разместите `index.html`, `README.md`, **всю папку `assets/` (включая НОВЫЙ файл `assets/norms.js`)** в корне репозитория.
2. В GitHub выберите Settings → Pages → Deploy from a branch → main/(root) и сохраните, если Pages ещё не включён.
3. После публикации обновите страницу через Ctrl+F5 (версия **2.6** должна отображаться сверху).
4. Перейдите в «Критика»: у нормативов будет надпись «НТЗ подключён автоматически»; для формирования нужны лишь две сегодняшние Excel-выгрузки.
5. Если автоматическое скачивание заблокировано браузером, используйте резервную ссылку под кнопкой экспорта.

## Конфиденциальность

**Критично:** GitHub Pages — статическая публикация. Встроенные `assets/norms.js` и `assets/etalon.js` доступны любому, кто имеет доступ к опубликованному сайту, включая значения НК/КК, их архив и коды номенклатуры. Если эти данные коммерчески конфиденциальны, **не публикуйте данную сборку в открытом доступе**. Для закрытой работы применяйте локальный запуск или защищённый хостинг с настоящей авторизацией, не только секретную ссылку. Два ежедневных XLSX обрабатываются в браузере, никуда не загружаются.

## Тесты

`node tests/core.test.cjs` проверяет исключение неподтверждённых кодов и правила объединения; `node tests/worker_integration.test.cjs` сверяет результат с реальными файлами. `node tests/builtin_ntz.test.cjs` проверяет работу справочника при пустом локальном хранилище, даты архивов, формирование критики и экспорт XLSX без импорта НТЗ. Остальные тесты в папке `tests` проверяют логику Excel, формулы, входные файлы и Эталон.

## Строгое правило источников (2.6)

- В ежедневный лист «Товарный запас», «Критика», «Цветы» включается код ТП **только при его фактическом наличии** в сальдово-оборотной ведомости ИЛИ уровне сервиса за выбранную дату. Сам по себе код в «Эталоне», НТЗ, архиве НТЗ или списке цветов **не создаёт строку**.
- Режим «Эталон» использует пересечение уникальных кодов Эталона с кодами, реально обнаруженными в ежедневных двух файлах. Повторы исключаются. Товары вне Эталона из ежедневных файлов показываются в «Контроле» и доступны в режиме «Все позиции из выгрузок».
- Лист «Эталон ТП» в готовом Excel содержит **только коды, которые нашлись в ежедневных источниках**, а не все коды эталонного справочника. Сам полный справочник сохранён на сайте в `assets/etalon.js` и в разделе «Эталон ТП».
- Если товар есть только в одном источнике, вторая часть показателей остаётся пустой. Название берётся только из исходных файлов или НТЗ; если оно нигде не указано, ячейка остаётся пустой. Выдуманных названий «Название не найдено» нет.
- В листе «Контроль» есть итоговое число кодов Эталона, исключённых из ежедневного отчёта из-за отсутствия в обеих выгрузках. Полные архивные справочные листы `НТЗ`, `Архив НТЗ`, `код цветы` не фильтруются и хранятся для истории.

Для принудительного обновления браузера у ресурсов сайта добавлен параметр версии `?v=2.6`. При публикации заменяйте целиком `index.html` и папку `assets/`.
