# МАГНИТ РЦ — версия 2.13

Статический сайт для GitHub Pages. Версия 2.12 добавляет новый раздел **«Претензии магазинов МАГНИТ»**, сохраняя модули товарного запаса, критики ТЗ, Эталона, возвратов ГТ и конструктора претензий Гранд-Трейд версии 2.8.

## Версия 2.13 — «Макрос» проверки палет

Откройте **«Макрос палет»** в боковом меню и загрузите **один** файл `.xlsx` — сводный отчёт по палетам. Название произвольное. Поддерживаются исходные колонки `номер`, `код`, `назв`, `МО`, `МП` и, если они есть, `актив`, `колич`, `Производитель`, `№ Прихода`, `Страна`.

Сайт автоматически формирует выборку и показывает проверочный лист. По умолчанию используется **3%** от реально подходящих палет (округление вверх), зона **Бафер 12–16**, как на распечатке менеджера. Процент и зону можно изменить.

**Фильтрация:** только свежие фрукты, овощи и зелень из фактических палет с положительным остатком и адресами МО / МП. Сайт применяет консервативный список названий свежей продукции и исключает очевидно переработанные продукты (соки, пюре, продукты с сахаром, заморозку, готовые салаты, консервацию и т. д.). Неопознанные позиции не включаются. Грибы не включены, потому что пользователь указал только фрукты и овощи.

**Необязательные параметры:**
- `Приоритетный код товара`: например, `3412070012` — при наличии включаются **до 5 палет** по коду, остальные добираются случайно из других товаров. Если кроме этого кода других товаров нет, ограничение 5 не применяется — отбор остаётся по проценту.
- `Поставщик`: строгий фильтр только по полям из исходного Excel: `Производитель`, `№ Прихода`, `Страна`. Для «Гранд-Трейд» распознаётся также идентификатор прихода `ГТАдг…` / `GTАдг…`. Если в файле нет подтверждений поставщика, сайт **не делает предположений и не создаёт отчёт по такому фильтру**.

Алгоритм выбирает случайные товарные **коды** для разнообразной выборки, затем палеты внутри товара; сортировка готового листа — по возрастанию адресов МП. Применяется псевдослучайный генератор с зафиксированным зерном. Нажатие **«Случайная выборка заново»** создаёт новую выборку, а зерно сохраняется в протоколе для воспроизводимости. Это алгоритм в JavaScript, **не встроенный VBA-макрос** Excel.

**Кнопка «Импорт в Excel по шаблону»** скачивает `.xlsx` с двумя листами:
1. `Проверка палет` — таблица в стиле распечатки: **номер, код, назв, МО, МП, пустой промежуток, Результат проверки**. Результаты осмотра остаются пустыми. Горизонтальный формат страницы для печати.
2. `Протокол отбора` — источник, параметры, количество кандидатов, количество выбранных палет, приоритет, дата и зерно случайной выборки.

При блокировке автоматической загрузки появляется резервная ссылка на тот же Excel. Ни один неподтверждённый код или адрес не добавляется.

**Проверка:** на предоставленном файле `pallet_summary (1)(1).xlsx` прочитано 12 805 палет, найдено 642 подходящие палеты в зоне Бафер 12–16, сформировано 20 строк при 3%; при приоритетном коде `3412070012` включены 5 палет с томатами. Фактический поставщик «ЭКО-КУЛЬТУРА-ТРЕЙД ООО (РЦ)» не подтверждается полем производителя в этом файле, поэтому фильтр по нему показывает честное предупреждение. Браузерный тест скачивания и проверка структуры XLSX пройдены.

**Обновление GitHub Pages:** заменить `index.html`, всю папку `assets/`, `README.md` из ZIP; сделать Ctrl+F5 и проверить версию 2.13. Важно: `assets/macro-core.js`, `assets/macro.js`, `assets/macro.css` — новые файлы, а `assets/export.js` обновлён.

## Претензии магазинов МАГНИТ

1. В меню открыть **«Претензии магазинов»**.
2. Загрузить Excel `.xlsx` из модуля претензий магазинов (`claims_export_...xlsx`). Можно загрузить **один файл**, который содержит обращения за оба дня, либо **несколько файлов по очереди**. Данные предыдущих файлов не пропадают, пока не нажата кнопка «Очистить загруженные файлы».
3. Указать дату окончания периода. Сайт автоматически берёт **этот день и предыдущий календарный день** по полю `Дата обращения`. При открытии раздела конечная дата заполняется по локальной дате браузера, но её можно изменить для исторических отчётов.
4. Выбрать **порог массовости** (по умолчанию 2 обращения; можно выбрать 1, 3, 5, 10).
5. Нажать **«Сформировать массовость»**. На экране появятся показатели, «Массовость по товарам», «Критика по характеристике товара». Кнопка «Обращения» раскрывает исходные данные конкретной группы. Поиск выполняется по товарам, характеристикам, производителям, магазинам.
6. При необходимости скачать Excel: **«Массовость», «Критика», «Все товары», «Обращения», «Контроль»**. Если браузер не начал скачивание, рядом появляется резервная ссылка.

### Поддерживаемый формат выгрузки

Формат проверен по исходному файлу `claims_export_2026-11-22T04_50_24.184790727Z.xlsx` с листом `Sheet0` и 56 столбцами. Обязательные названия:

- `Код товара`
- `Наименование товара`
- `Дата обращения`
- `Характеристика товара/прихода`
- `Производитель`

Дополнительные используемые названия: `guid`, `id`, `Код ТО`, `Наименование ТО`, `Филиал`, `Кол-во брак`, `Комментарий ТО`, `Причина списания`, `Статус`.

**Правила обработки:**
- В отчёты попадают только фактические обращения за выбранные два дня. Коды и названия товаров не создаются из Эталона или НТЗ.
- Записи без реального кода товара, наименования или корректной даты обращения пропускаются. Неизвестные производители и характеристики остаются пустыми, а не заменяются придуманными.
- При повторной загрузке одна претензия с тем же `guid` считается один раз. Если `guid` отсутствует, используется `id`, а затем фактические поля строки.
- Массовость по товару считается по коду товара. Критика — по коду товара и характеристике; варианты « Гниль» и «Гниль» объединяются при группировке, но исходное значение сохраняется в листе «Обращения» после удаления лишних пробелов.
- Количество магазинов — количество уникальных кодов `Код ТО` (если код отсутствует, используется название магазина).
- Исходный производитель остаётся неизменным. Отдельное производное поле «Поставщик»: любое упоминание `GT`, `ГТ`, `PGT`, `BGT`, «Гранд-Трейд», `Grand Trade`, «Турция» (включая регистр и варианты написания) в строке обращения определяет поставщика **«Гранд-Трейд»**. Без упоминания поставщик остаётся пустым (не выдумывается).
- Если за один из дней нет обращений, сайт сообщает об этом; дата никогда не подменяется.
- В отчёте «Контроль» сохраняются количество повторов, даты, выбранный порог и показатели периода.

### Установка

Содержимое архива загрузить в **корень репозитория**, включая `index.html`, `assets/` и `README.md`. В GitHub Pages выбрать публикацию из нужной ветки. Обновить страницу в браузере `Ctrl+F5`, убедиться, что указан номер версии **2.12**. Никакие серверные API или ключи не требуются; Excel обрабатывается локально в современном Chrome / Edge.

### Безопасность

**Не публикуйте конфиденциальные выгрузки претензий в GitHub.** Загруженные пользователем Excel-файлы обрабатываются в браузере и не отправляются на сервер. Однако исходная сборка содержит встроенные справочники НТЗ / Эталон из предыдущих версий сайта: если разместить эту сборку в **публичном** GitHub Pages, встроенные справочники станут общедоступны. Для конфиденциальных нормативов нужен защищённый способ размещения.

### Технические файлы

- Исправлено подключение кнопки «Очистить загруженные файлы»: раньше обработчик обращался к отсутствующему элементу и прерывал инициализацию дальнейших обработчиков, включая скачивание Excel.

## Версия 2.12 — поставщик Гранд-Трейд

- В разделе «Претензии магазинов МАГНИТ» автоматически определяется **поставщик Гранд-Трейд** по любому упоминанию GT / ГТ / BGT / PGT / Гранд-Трейд / Grand Trade / Турция в исходной записи обращения. Пример: `Турция`, `PGT-782544`, `bgt-780789`, `израиль GT 780855`, `АО «Гранд-Трейд»`.
- Поле «Производитель» остаётся без изменений и отображается отдельно от поля «Поставщик». Если ни одного признака нет, поставщик не приписывается.
- В группах, где часть обращений не имеет признака Гранд-Трейд, показывается точная доля (например, «Гранд-Трейд (24 из 38)»), чтобы не приписывать все обращения одному поставщику. Поставщик показывается в «Массовости», «Критике» и в деталях обращений. В итоговом XLSX — отдельный столбец «Поставщик», а в «Обращениях» ещё и исходное поле-основание определения. Поиск поддерживает «Гранд-Трейд».
- Фильтр двух дней, дедупликация `guid` и подсчёт массовости не изменены.
- Для публикации обновите `index.html`, `assets/store-claims-core.js`, `assets/store-claims.js` и `README.md` (проще заменить весь комплект) и обновите страницу Ctrl+F5.


## Версия 2.12 — редактирование поставщиков без загрузки дополнительного Excel

- Встроены 2 новые записи производителя, определяемые как «Гранд-Трейд»: «ЧИНАР АМБАЛАЙ НАКЛИЙАТ ТУРИЗМ ИНСААТ МАКИНЕ ПЕТРОЛ ТАРИМ УРУНЛЕРИ САНАЙИ ВЕ ТИКАРЕТ ЛИМИТЕД СИРКЕТИ» и «пьюр кроп гида тиджарт аноним шикркти».
- В разделе «Претензии магазинов» появился редактируемый **Справочник поставщиков**: добавить/перезаписать соответствие производителя и поставщика, изменить существующее правило, удалить пользовательское или восстановить встроенное.
- В деталях обращений рядом с полем поставщика доступна **ручная правка конкретного обращения** («Сохранить») и **массовая правка по наименованию производителя** («Для производителя»).
- После правок таблицы массовости, критики, детали, поиск, показатели и Excel пересчитываются. Исходное значение «Производитель» остаётся как в Excel, ручные изменения помечаются в колонке «Основание определения поставщика».
- Пользовательские правила и индивидуальные исправления сохраняются в `localStorage` текущего браузера. В справочнике доступны экспорт/импорт JSON для переноса правил между устройствами. На GitHub и другим пользователям локальные правки автоматически не передаются.
- При очистке хранилища браузера пользовательские правки будут утрачены, если не экспортировать их заранее; базовые две новые записи находятся в коде сайта и сохраняются.
