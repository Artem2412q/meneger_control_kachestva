# МАГНИТ РЦ — автоматизация Excel-отчётности

Адаптивный статический сайт для **GitHub Pages**, без сервера и без отправки исходных Excel-файлов куда-либо. Интерфейс — на русском языке.

## Что работает

- Категория **«Товарный запас»**. Каждый день нужно выбрать **два файла** с точными именами:
  1. `rep_turnover_saldo_for_logist_excel.xlsx` — сальдово-оборотная ведомость;
  2. `rpt_levelservice_api.level_service_hd_gk_eday_hm.xlsx` — уровень сервиса по товарным позициям.
- Проверяется имя, расширение `.xlsx`, наличие обязательных столбцов.
- Отчёты объединяются **по полю «Код товара»**, операции уровня сервиса суммируются по коду товара **и дате операции**.
- Дата автоматически читается из второго файла. При нескольких датах можно выбрать нужную (дата должна присутствовать в данных).
- Уровень сервиса считается как **отгрузка/заказ** и **отгрузка/импорт**; товарный запас — **конечный остаток/отгрузка**, а «ТЗ/Заказ» — **конечный остаток/заказ**. `Vicherk` суммируется из исходного одноимённого поля.
- При нулевом знаменателе числовой показатель равен нулю. Если **заказ = 0**, в двух итоговых комментариях ставится **«Без расхода»**, как в образце.
- Готовый `.xlsx` содержит датированный лист (16 полей, с формулами), «НТЗ», «УС» и «Контроль».
- Категория **«Возвраты ГТ»**: загрузка, проверка обязательных полей, просмотр, поиск и экспорт отфильтрованных строк в `.xlsx`. Форматирование и оформление оригинала при экспорте не сохраняются.
- Установка сайта не требует серверной части, регистраций, платного API или хранения файлов на GitHub.

## Первый запуск и справочник НТЗ

В двух ежедневных файлах **нет нормативов НК / КК**. Они находятся на листе «НТЗ» в образце `Отчет по Товарному запасу Ноябрь 2026 год(1).xls`.

Один раз откройте раздел «Товарный запас» → «Загрузить образец .xls / .xlsx» и загрузите исходный образец. Сайт извлечёт нормативы НК/КК и коды товаров последнего датированного листа, сохранит их в **localStorage только этого браузера**. Затем ежедневно загружайте **только два исходных файла**. Можно удалить справочник кнопкой «Удалить локальный справочник».

Если нормативов нет или для кода не найден норматив, в итоговом файле НК/КК и отклонения **пустые**, а лист «Контроль» перечисляет такие позиции — никаких вымышленных значений.

### Режимы выбора строк

- **По списку из образца** (с установленным образцом) — включаются коды из последнего датированного листа образца, имеющиеся в одной из двух новых выгрузок.
- **Овощи и фрукты** — используется тип отбора `Овощи-фрукты`, признаки группы из ведомости и коды образца. Этот режим является **предварительной эвристикой**, а не подтверждённым рабочим фильтром.
- **Все товары** — все встреченные в ведомости или уровне сервиса коды.

**Важно:** в образце есть более сложные правила выбора позиций и листы архива. Точные правила отбора и сохранения старого оформления ещё предстоит согласовать по рабочему примеру. Версия 1.0 **воссоздаёт расчёты** и генерирует новый `.xlsx`, **но не изменяет** исходный месячный `.xls` и не сохраняет его сводные таблицы, скрытые листы или оформление один-в-один.

## Публикация на GitHub Pages

1. Создайте репозиторий GitHub, например `magnit-rc-site`.
2. Разместите в **корне репозитория** `index.html`, папки `assets` и `tests`, а также этот `README.md`. Не загружайте исходные отчёты, включая образец `.xls`.
3. Откройте **Settings → Pages → Build and deployment → Deploy from a branch → main → /(root) → Save**.
4. Дождитесь публикации: сайт будет доступен по адресу вида `https://<логин>.github.io/magnit-rc-site/`.

Сайт использует внешний JS-файл **SheetJS Community Edition 0.20.3** по официальному HTTPS CDN `cdn.sheetjs.com` для чтения `.xls/.xlsx` и экспорта `.xlsx`. Это не является серверной обработкой загруженных таблиц: скрипт исполняется **в браузере пользователя**, но требуется доступ к CDN. Для полностью изолированной локальной сети библиотеку можно скопировать в `assets` и заменить URL в `index.html` и `assets/worker.js` на локальный файл. Убедитесь, что правила ИБ организации разрешают используемую библиотеку/внешние скрипты.

**Конфиденциальность:** опубликованные GitHub Pages доступны в интернете. Нельзя размещать коммерческие отчёты в репозитории, даже если репозиторий закрыт. Статический сайт не отправляет загруженные данные на сервер. Локальный справочник хранится в браузере и не синхронизируется между устройствами.

## Проверка алгоритма

Тесты выполняются в Node.js (без npm-зависимостей):

```bash
node tests/core.test.cjs
node --check assets/core.js
node --check assets/worker.js
node --check assets/app.js
```

## Известные ограничения версии 1.0

- При повторяющихся кодах в сальдовой ведомости используется последняя запись и генерируется предупреждение. Правило разрешения дублей нужно уточнить.
- Если код уровня сервиса не найден в сальдовой ведомости, начальный и конечный остатки временно считаются 0, а код заносится в лист «Контроль». Это не подтверждённая бизнес-логика.
- При нескольких РЦ в одном документе суммы сейчас не разбиваются по РЦ; можно доработать фильтр РЦ.
- Очень большие Excel (100+ тыс. строк) могут потреблять значительную память браузера; чтение выполняется в Web Worker, чтобы не блокировать интерфейс.
- Лист «УС» содержит агрегаты с использованием полей из второго исходного файла. Для буквального воспроизведения истории, оформления, цветов и сводных таблиц исходного месячного файла нужен отдельный этап проверки.
- Реестр «Возвраты ГТ» пока поддерживает поиск и экспорт, не включает специфический согласовательный процесс, который пользователь ещё не показал.

## Дальнейшее обучение автоматизации

В файле `assets/core.js` сосредоточена чистая бизнес-логика расчёта. Когда будут предоставлены дополнительные инструкции, можно уточнять правила, проверять их на примерах и добавлять новые категории без переписывания сайта.
